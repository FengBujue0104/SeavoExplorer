# SeavoExplorer 主板项目文件浏览器

**版本 0.6.7**

Windows 单文件版可从 [v0.6.7 Release](https://github.com/FengBujue0104/SeavoExplorer/releases/tag/v0.6.7) 下载。发布页同时提供独立 SHA-256 文件和 build manifest；下载后应核对附件中的哈希。

---

## 适用范围

SeavoExplorer 是一个 Windows 桌面工具，用于浏览以 S/M 编号命名的主板、子卡项目文件夹。程序可扫描配置的项目根目录，快速定位项目，预览常见工程文档，并创建标准化项目/版本文件夹结构。

---

## 主要功能

### 1. 项目扫描与分类

- 自动识别以 S 或 M 开头、后跟 3~4 位数字的项目文件夹
- 支持可选的 `_注释` 后缀，例如 `S001_样机`、`M1234_说明`
- 支持主板/子卡分区显示、项目搜索、按编号排序、递归扫描子文件夹
- 支持项目置顶、隐藏项目，以及恢复已隐藏项目

### 2. 文件树浏览

- 单击左侧项目后，在右侧文件树中显示项目内容
- 单击文件可预览内容并查看元数据
- 双击文件使用系统默认程序打开
- 双击文件夹或空白区域可在 Windows 资源管理器中打开对应目录
- 右键可在资源管理器中选中当前文件/文件夹，或复制完整路径、相对路径（纯文本，支持多选）
- 菜单「占用分析」或点击状态栏文件统计，可列出当前项目最大的文件，双击即可在资源管理器中定位

### 3. 文件预览

| 文件类型 | 支持格式 | 说明 |
|---------|---------|------|
| 文本文件 | .txt .csv .log .bom .drc .rep .rpt .md .json .xml .html .htm .ini .cfg | 直接显示文本（UTF-8/GBK 自动识别，支持 BOM） |
| PDF 文件 | .pdf | 预览前 3 页文本 |
| Excel 文件 | .xlsx .xlsm .xls | 表格预览 |
| Word 文件 | .docx .doc | 文档预览 |
| 图片文件 | .jpg .jpeg .png .bmp .gif .tiff .tif .webp .svg | 缩略图 + 大图查看器 |
| 视频文件 | .mp4 .avi .mov .mkv .flv .wmv .m4v .webm .mpg .mpeg .3gp | 5 帧截图（10%/30%/50%/70%/90% 位置），需 OpenCV |
| 压缩包文件 | .zip .rar .7z | 树状结构展示 |
| 工程文件 | .opj .dsn .sch .brd .dbk .dsnlck | 不直接解析，显示不可预览提示 |

> **预览开关**：在「设置 → 预览设置」中可按类型关闭自动预览；关闭后仍可对当前文件点击「显示预览」。RAR/7Z 还需要在「7-Zip 路径设置」中显式启用并选择可信的官方 `7z.exe`，ZIP 不受该授权开关影响。 为避免大列表或大表格拖慢界面，压缩包预览最多列出 5000 项、2 MiB 输出；Excel 预览最多显示 20 个工作表、每表 10 行和 64 列。

### 4. 文件操作

- 支持从程序内或 Windows 资源管理器复制文件/文件夹，再粘贴副本、重命名、移入回收站
- 支持 Ctrl/Shift 多选后批量复制、批量复制路径、批量压缩、批量归档、批量移入回收站
- 粘贴副本和保存版本使用独占临时文件及无覆盖提交，重名时自动换名，绝不静默覆盖已有文件
- 多选压缩会合并父子路径、排除输出 ZIP 自身并按归档成员名去重；支持读取系统剪贴板中的本地文件和文件夹
- 删除操作使用 Windows 10/11 的强制回收站接口；目标位置不支持回收站时会报错并保留原文件，不会降级为永久删除
- 支持 Ctrl+Z 撤回最近一次重命名、粘贴副本、保存版本、创建压缩包或归档到 old/；撤回创建类操作会把新文件移入回收站，原位置被占用时拒绝覆盖，未完成的撤回会保留并可再次尝试

#### 🆕 显示隐藏文件

菜单 **设置 → 显示隐藏文件**（可勾选开关），或 **设置 → 项目文件夹设置** 中勾选。勾选后在文件树中显示以 `.` 开头的文件（如 `.gitignore`）和系统隐藏属性的文件。

- 面包屑路径栏支持双击任意目录段直接用资源管理器打开该目录，单击仍用于在文件树中定位

#### 保存版本

右键文件选择「保存版本」，自动生成 `文件名_YYYYMMDD[后缀].ext` 的副本：

- 当天第一个版本：`S1200-10_20260708.dsn`
- 当天第二个版本：`S1200-10_20260708a.dsn`
- 当天第三个版本：`S1200-10_20260708b.dsn`
- 后续版本始终接在当前已存在的最大后缀之后；例如只有 `...c.dsn` 时，下次保存生成 `...d.dsn`，不会回填无后缀、`a` 或 `b` 版本；单个字母用完后自动续接 `aa`、`ab`…
- 目标名称已存在（含仅大小写不同）时会自动跳过改用下一个后缀，绝不覆盖已有文件；当天后缀全部占用时明确提示已达上限
- 若文件名末尾已有 `_YYYYMMDD` 或 `_YYYYMMDD[a-z]` 后缀，会剥离后重新生成，避免日期重复

#### 🆕 归档到 old 文件夹（0.5.0 新增）

右键选择「归档到 old 文件夹」，将选中文件/文件夹移入同目录下的 `old/` 子文件夹：

- 支持多选批量归档
- 无 old 文件夹时自动创建
- 重名时自动追加数字（`file_1.ext`、`file_2.ext`）

#### 🆕 自定义项目正则（0.5.0 新增）

在「设置 → 项目文件夹设置」中可切换「默认」或「自定义正则」：

- **默认**：主板 `^S(\d{3,4})(?:_(.*))?$`，子卡 `^M(\d{3,4})(?:_(.*))?$`
- **自定义**：分别为主板和子卡输入正则表达式并测试匹配结果
- 自定义表达式必须至少提供 1 个捕获组：组 1 是可转换为整数的项目编号；组 2 可选，作为注释；编译失败或无效时回退到默认规则
- 保存前会进行安全校验：嵌套重复组、变长量词重复等常见灾难性回溯（ReDoS）结构会被拒绝；可选组（如 `(-\d+)?`）不受影响。该检查是结构启发式，不能保证覆盖所有复杂正则
- 设置自动保存到 `seavoexplorer.json`

### 5. 压缩包操作

- `.zip` 使用 Python 内置能力进行预览和解压
- `.rar` 和 `.7z` 依赖外部 7-Zip（7z.exe）进行列表读取和解压，默认不授权；请只选择官方可信程序
- 支持「智能解压」：先在同盘安全临时目录中预检并解压，校验完成后再提交；包内只有一个顶层项目时直接放到当前目录，多个顶层项目时创建同名文件夹
- 解压目标重名时自动追加 `(1)`、`(2)`，不覆盖现有文件；非法路径、链接、异常压缩比或空间不足时会取消并清理临时结果
- 支持将单个或多个选中项目添加到 zip 压缩包

### 6. 检查更新

- 点击「帮助 → 检查更新」即可从 GitHub Releases 检查最新版本
- 程序目录可写且新版本提供 SHA-256 digest 时，弹窗提供「下载并更新」：程序退出后由新 EXE 等待旧进程结束、替换原 EXE 并重新启动
- 程序目录不可写或缺少 digest 时只能「仅下载」，之后手动替换
- 应用内下载支持后台进度显示、重试和断点续传
- 当前发布使用自签名证书，Windows 可能提示「未知发布者」；请核对发布页的 SHA-256 和 manifest

### 7. 快捷访问栏

- 可在「设置 → 快捷访问设置」中配置常用目录按钮
- 普通快捷按钮会在程序文件树中显示目录内容
- 「不显示预览」按钮会直接用资源管理器打开，适合磁盘根目录、网络目录等大目录

### 8. 新建项目与版本结构

- **新建项目文件夹**：按 S/M 类型、编号、注释和目标位置创建项目根目录
- **新建文件夹内部结构**：在选中项目内创建版本目录（如 V01）和标准子文件夹（BOM、SCH、物料、评审、信号测试），也支持自定义子文件夹
- 上次选择的内部结构模板会自动保存，便于重复使用

### 9. 视频预览与大图查看（0.5.0 新增/改进）

- **多帧视频预览**：视频文件显示 5 张截图，分别在 10%/30%/50%/70%/90% 时间位置
- **视频默认关闭**：需在「设置 → 预览设置」中手动开启
- **视频帧查看器**：点击预览图可打开帧查看器，左右方向键（← → ↑ ↓）或底部「◀ 上一张」「下一张 ▶」按钮切换帧
- **大图缩放与拖拽**：图片/视频帧大图支持滚轮缩放、底部「−」「+」「1:1」按钮缩放、左键拖拽平移
- **面包屑路径栏**：文件树上方显示从项目根到当前点选项的路径；单击任意目录段可在文件树中定位，双击任意目录段可直接用资源管理器打开该目录
- **状态栏文件统计**：选中项目后，状态栏右侧常驻显示该项目递归的文件数与总大小
- **记住窗口与项目**：退出时记住窗口大小/位置、左右分栏宽度、是否最大化，以及上次打开的项目
- **已禁用全屏模式**，避免菜单与关闭按钮不可见

## 打包程序

官方构建依赖固定在 `requirements-build.txt`。正式构建必须使用未启用 `system-site-packages` 的专用虚拟环境；除 venv 自带的 `pip`/`wheel` 外，脚本会拒绝全局 Python 和任何锁外发行包：

```powershell
python -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install -r requirements-build.txt
```

两个包装器都使用同一个权威配置 `main.spec`，默认离线执行版本/资源检查、Python 3.8 grammar、`py_compile`、156 项回归测试、PyInstaller 构建、二进制来源审计和净化环境下的隔离启动冒烟；不会自动安装依赖或重生成图标。

### 单文件 exe

```powershell
.\.venv-build\Scripts\python.exe build_onefile.py
```

输出：

- `dist/SeavoExplorer.exe`
- `dist/SeavoExplorer.exe.sha256`
- `dist/SeavoExplorer.build.json`

### 单目录分发包

```powershell
.\.venv-build\Scripts\python.exe build_onedir.py
```

输出目录：`dist/SeavoExplorer/`；分发时必须包含整个目录。目录内的 `SeavoExplorer.directory.sha256` 按排序后的相对路径记录全部 payload 文件，build manifest 记录文件数、总大小和该清单的树哈希。

### PyInstaller spec 方式

```powershell
.\.venv-build\Scripts\python.exe -m PyInstaller --noconfirm --clean main.spec
```

直接调用 spec 默认生成 onefile，但不会执行包装器提供的测试、产物 manifest 和冒烟流程，正式构建应优先使用 `build_onefile.py`。完整环境、校验和发布步骤见 `打包指南.txt`。

### 代码签名

- 当前发布使用自签名证书进行 Authenticode 签名，但证书未受公共信任，Windows SmartScreen 仍可能提示“未知发布者”。
- 开发者可用 `.\make_self_signed_cert.ps1 -PfxPassword "<密码>"` 生成自签名证书，再按 `打包指南.txt` 设置 `SEAVO_SIGN_MODE=store` 构建签名版。
- 正式发布建议使用 SignPath Foundation 或商业 OV/EV 证书。

## 常见问题

### 1. 找不到项目

- 检查项目根目录是否已在「设置 → 项目文件夹设置」中添加
- 检查文件夹命名是否符合 S/M + 3~4 位数字规则
- 如果项目位于更深层目录，请启用「包含子文件夹」

### 2. .rar 或 .7z 无法预览/解压

- 从 7-Zip 官方渠道安装程序，在「设置 → 7-Zip 路径设置」中显式启用并指定可信的 7z.exe
- 程序会依次查找：设置路径、程序目录下的 7z.exe、系统默认安装目录

### 3. 更新下载慢或失败

- 先在「帮助 → 检查更新」里尝试应用内下载
- 如果程序目录可写且下载文件带 SHA-256 digest，弹窗会提供「下载并更新」：程序退出后由更新文件等待旧进程结束、替换原 EXE 并重新启动；若替换和回滚都失败，会同时保留旧程序 `.old` 备份与已下载的新 EXE
- 如果程序目录不可写（例如 Program Files）或缺少 digest，只能「仅下载」后手动替换
- 自签名或未签名版本在 Windows 上仍可能提示「未知发布者」；请核对发布页提供的 SHA-256 和 manifest
- 断点续传会尽量利用已经下载的部分文件

### 4. 大目录加载慢

- 避免把磁盘根目录作为普通预览入口
- 可将大目录加入快捷访问，并勾选「不显示预览」

### 5. 预览乱码

- 文本预览会尝试 UTF-8 和 GBK 编码
- 若仍乱码，请用专业编辑器或文件对应软件打开

### 6. 打包失败提示无法覆盖 exe

- 通常是 `dist/SeavoExplorer.exe` 正在运行或被占用
- 关闭已运行的程序后重新执行打包脚本
- 若提示构建环境版本不一致，请按 `requirements-build.txt` 创建 Python 3.13.2 x64 专用环境；仅本地试验时才使用 `--allow-unverified-env`
